# Uptime Checker 🚀

Компактна утиліта командного рядка для моніторингу доступності вебсайтів та HTTP API. Програма читає список цілей з YAML-конфігурації, послідовно виконує GET-запити, вимірює час відповіді та формує зрозумілий звіт у консолі або у форматі JSON.

## 📌 Вимоги
* Підтримувана версія Python: **3.12+**
* Інтернет-з'єднання для перевірки реальних вузлів.

## 🛠 Встановлення та налаштування

Проєкт використовує віртуальне середовище для ізоляції залежностей. Виконайте ці кроки для розгортання:

1. **Клонуйте репозиторій та перейдіть у папку:**
   ```bash
   git clone "https://github.com/vanaveduta228-boop/uptime-checker.git"
   cd uptime-checker

```

2. **Створіть віртуальне середовище:**
```bash
python -m venv venv

```


3. **Активуйте віртуальне середовище:**
* **Windows (PowerShell):**
```powershell
.\venv\Scripts\Activate.ps1

```


* **Linux / WSL:**
```bash
source venv/bin/activate

```




4. **Встановіть залежності:**
```bash
pip install -r requirements.txt

```



## ⚙️ Додавання нової адреси (Конфігурація)

Всі цілі для перевірки зберігаються у файлі конфігурації YAML. Для старту скопіюйте приклад:
`cp config.example.yaml config.yaml` *(для Linux)* або просто створіть файл вручну.

Щоб додати новий сайт, додайте новий блок у список `targets`:

```yaml
targets:
  - name: MyNewSite
    url: "https://mynewsite.com/api"
    expected_status: 200
    timeout_seconds: 10
    slow_threshold_ms: 3000

```

*Жодних змін у коді Python для додавання нових сайтів не потрібно!*

## 🚀 Запуск перевірок

Для ручного запуску перевірки використовуйте команду:

```bash
python -m uptime_checker --config config.yaml

```

**Приклад результату в консолі:**

```text
[OK] Slotelle | HTTP 200 | 245 ms
[WARN] Example | HTTP 200 | 3500 ms 
[FAIL] API | Таймаут після 10 s

Разом: 3 | OK: 1 | WARN: 1 | FAIL: 1

```

**Генерація JSON-звіту:**
Якщо потрібно зберегти результати (наприклад, для подальшого аналізу), додайте прапорець `--output`:

```bash
python -m uptime_checker --config config.yaml --output report.json

```

## 🧪 Запуск тестів

Проєкт покритий автоматичними тестами, які не потребують підключення до інтернету (використовуються заглушки HTTP-відповідей). Для перевірки логіки запустіть:

```bash
pytest

```

## 📊 Значення статусів та кодів завершення

**Статуси перевірки:**

* `[OK]` — Отримано очікуваний HTTP-статус, час відповіді не перевищує поріг.
* `[WARN]` — Очікуваний статус отримано, але час відповіді перевищив `slow_threshold_ms`.
* `[FAIL]` — Неочікуваний HTTP-статус, таймаут або мережева помилка (DNS, відмова з'єднання).

**Коди завершення (Exit Codes):**

* `0` — Перевірка пройшла успішно (немає жодного FAIL, попередження WARN допускаються).
* `1` — Хоча б одна перевірка завершилася зі статусом FAIL.
* `2` — Критична помилка конфігурації (файл не знайдено, хибний формат YAML, відсутні обов'язкові аргументи запуску).
